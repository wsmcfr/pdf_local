读图要点

这七条是理解 Trellis 运行时行为的关键。

1

init 只负责“铺文件”：.trellis/ 提供流程、任务、规范、脚本；平台目录提供 skill、command、agent、hook 注册。

2

workflow.md 是流程唯一事实源：每轮提示由 hook 解析 [workflow-state:STATUS] 块得到，不是硬编码在脚本里。

3

SessionStart 管“开局”：注入项目状态、workflow 摘要、spec 索引、当前任务状态。

4

UserPromptSubmit 管“当前阶段”：解析 active task 的 task.json.status，给出 no_task / planning / in_progress 面包屑。

5

PreToolUse 管“子 Agent 上下文”：按 implement.jsonl / check.jsonl 把 spec、research、prd、design、implement 注入子 Agent prompt。

6

子 Agent 不提交：trellis-implement / trellis-check 被禁止 git commit / push / merge，提交由主会话在 Phase 3.4 统一做。

7

channel 是重型分支：需要多轮对话、可中断 worker、持久事件日志时才用；普通任务直接走平台子 Agent。

说明：图中的 .claude/ 只是 Claude Code 的示例路径；同一套 Python hook 会被复制到 Trae、Cursor、Codex 等平台的对应目录，并由各平台的 settings.json / hooks.json 注册。
